## 3. L138/L139 — pool pruning is CLOSED, both halves failed

The question was cost, not quality. L137's clean timing established that the
binding term of M67-E's wall model is `max_k dt_k`, not `sum_k dt_k / cores`
(case 99: max 1.542s vs sum/48 0.883s), so the per-case wall is ONE profile's
runtime. L138 then measured that dropping the 10 slowest PER CASE cuts the
weighted wall **12.95%** with the winner preserved on 12/13 heavy cases.

That was an upper bound, not a result, and L139 closed it from both sides.

**Deployable version is 3.03%, and it plateaus.** One FIXED set of the 33
profiles that never win across 41 in-set heavy cases buys 1.2632s → 1.2249s, and
nothing more from size 21 onward. The reason is structural: of 23 distinct
max-setters, **9 also win somewhere**, so dropping the 14 that never win just
promotes those nine. They are the floor and cannot be removed without losing the
cases they win. M41/M42 already took the outliers; the remainder is a flat
distribution whose top is load-bearing.

**And the fixed set does not survive out of sample.** Measured directly on 22
held-out OOS cases with the same harness:

| | cases | distinct winners | winner REMOVED by the drop set |
|---|---|---|---|
| in-set (fitted here) | 41 | 18 | **0/41** |
| **OOS s1 (held out)** | 22 | 15 | **12/22** |

The 0/41 is by construction — the greedy stopped the instant a winner moved. On
held-out cases the same set deletes the selected profile on **55%** of them.

🔑 **"Never wins" is a property of the sample, not of the profile.** The two
bands draw overlapping-but-different winner sets from 51 profiles, so any drop
set fitted on one sample is fitting that sample. This is M67-D's precedent made
quantitative: it measured the adaptive cuts' OOS quality tax at +2.825% against
an in-set +0.106%, a 27x gap; here the same shape reads 0% in set and 55% out.

Full detail in `L139_REPORT.md`. The remaining ways to cut wall do NOT go through
the pool: make the load-bearing profiles faster, or cut work inside a profile,
which is what L137's `ICCAD_HINT_REFINE` does.

## 4. 🚨 Silent-failure notes (this session's four)

08-16 §5's list still applies. These are new, and every one produced numbers that
looked entirely reasonable.

1. **`--dt 0` is an ASSUMPTION that reads like a measurement.** It tells the probe
   the candidate is free, so `dRF@48c = +0.000%` is a tautology. Real values were
   +38.3% / +31.7%.
2. **A tool's own hygiene can delete your experiment.** `m77_oos_probe` strips
   every `ICCAD_*` at import — correct for its job — and `l137_oos_ab.py` imported
   it before reading the knob, producing two **byte-identical** 240-case arms: a
   clean, plausible, completely empty A/B. Capture knobs BEFORE the import and
   print requested-vs-actual.
3. **`verify` does not re-stage.** The first `build_submission.L136FIX/` I saved
   carried the OLD Linux binary because the last `stage` predated the swap. Scores
   were unaffected (Windows never reads the bundle) — only the artefact was wrong.
   Stage after every input change and check md5s in the STAGED tree.
4. **The gate's wall-clock cannot measure a few percent.** Re-running identical
   arms moved the baseline's own wall 4.225s → 5.051s, a **19.6% spread**. Costs
   are bit-identical across repeats (the placer is deterministic), so quality is
   safe; timing is not. Use per-profile min-of-N through
   `max(max dt, sum dt/cores)`. I stated "faster AND better" off the noisy number
   and had to withdraw it.

🔑 The pattern in all four: **the tool ran, the numbers were plausible, and the
thing being measured was not the thing intended.** What caught each was an
internal consistency check, never the result looking wrong — e.g. cap6 (6 passes)
cannot be slower than no-cap (12).

🔑 And the standing rule that was mis-applied: **L125's "price it before building"
means price what the mechanism costs when DEPLOYED, not how long its code runs.**
Pricing only the new code missed the hint's effect on the consumer by 3×.
