## 2. In flight: L120, the LR shape solver

Lives in the SCREEN tree (`C:\ICCAD_ml\teammate_m71_screen`), **untracked**:
`l120_lr_solver.py`, `l120_lns_ceiling.py`, plus a modified `l100_lp_speed.py`.

**Goal is not "a faster LP".** It is to make the shape step EXACT (`w*h = A` held
exactly, closed form per module) so depth is not needed. Today the area
constraint is linearised, which caps the trust region at rho=0.06; rho=0.10
keeps 0/100 passes. Reaching a large aspect change therefore costs ~12 passes,
and k=12 needs **8.43x** on the LP to break even.

Priced: k=12 quality at 1x one pass = grid worst **+4.816%** against today's
+1.674%; at 1.5x +2.693%; **at 2x only +0.622%** ⇒ **budget is < ~1.8x one LP pass.**

### Facts established while building it

- **`min(XMAX - XMIN) = -shortestPath(XMAX -> XMIN)`** holds on all 100 cases.
  With shapes frozen, every shipped row is a difference constraint: separations,
  envelope, bbox, boundary equalities (two inequalities each), variable bounds.
- **The unit-level graph is not guaranteed acyclic** (two rigid clusters can each
  own a block on either side of the other), hence Bellman-Ford rather than a
  topological pass. Measured: **0 negative cycles** on 100 cases — measured, not
  assumed.
- **`a` and `b` are just sums of multipliers.** `dw`/`dh` appear in every shipped
  row with coefficient exactly **+1.0** (separation `:361`, boundary-far
  `:405/:415`, envelope-far `:427/:433`) and nowhere else once the area band is
  dropped; all those rows are `<=` so their multipliers are >= 0.
- **I optimised the wrong thing first.** Vectorising the Bellman-Ford relaxation
  bought 1.17x. Profiling then showed the split was **build_graph 39.8ms (95%) /
  relaxation 1.6ms (5%)** — the O(n^2) Python pair scan was the constant, and
  `diff_system` was re-running it once per axis when it computes both anyway.
  Fixing those gave the 3.4x. **Profile before optimising.**

## 3. 🚨 The open decision that blocks L-4

`solve_layout` (pure re-compaction, shapes UNCHANGED) stays feasible and
`hard_ok` on 5/5 cases — but **every case gets worse**:

| case | before | after re-compaction |
|---|---|---|
| 60 | 1.163270 | 1.172117 |
| 99 | 1.277263 | **1.326781** |
| 95 | 1.194646 | 1.197740 |

Not a bug — a different objective. L-2 minimises AREA; the official cost is
`1 + 0.5*(hpwl + area)`, and squeezing the bbox pushes wirelength up by more
than the area saved. **Classic LR handles area only, and our objective is half
HPWL — dominant on the heavy cases (gap 0.15-0.36 vs area 0.10-0.23).**

Three ways forward, not yet chosen:

- **Ⓐ relax HPWL into the multipliers too.** Sound, but `t >= |z|` is two rows
  per edge and case 99 has 7056 b2b edges ⇒ multiplier count explodes.
- **Ⓑ add a min-cost-flow component.** Correct (minimising HPWL under difference
  constraints is MCF's dual) but heavy, and a pure-Python MCF will hit the same
  constant wall L-2 just did.
- **Ⓒ alternate: positions by LP (keep HiGHS and the HPWL objective), shapes by
  L-3's closed form.** Cheapest, and it attacks the actual bottleneck — the rho
  trust region — rather than the position step. Still pays one LP per round.

**My recommendation was Ⓒ**, because the budget analysis says the position step
is only ~0.3x of the budget; what is unaffordable is *twelve rounds*, not one
round. If exact shapes collapse 12 rounds into 2-3, it fits.

## 4. Things that will silently mislead you

1. **`rows_for_k()` degrades silently.** It slices `r["passes"][:k]` and takes
   the last kept cost. Fed a file with ONE pass per case — which is what
   `results_L100_lp_speed.json` is — it returns **k=1 quality for every k**, so
   depth is charged its time and credited none of its quality. It prints a clean
   monotone ladder while doing this. **Use `results_L118_depth12.json`** (100
   cases x k=12, prune+sep_trim, min of 3, 741 passes / 655 kept).
2. **Same-corpus 5-fold CV over-predicts.** M81 arm ② won +0.115pp on 5-fold and
   lost −0.084pp (s1) / −0.002pp (s2) on true OOS. The project already knew
   in-sample lies; CV only reshuffles folds, the CASES are still the same 100.
   **Ship decisions need 240x2 disjoint samples @48c, NET bar 0.30%.**
3. **The 48-core lane is not bit-reproducible across platforms.** Windows scipy
   1.15.3 vs Linux 1.18.0 land on different optima of the same degenerate LP:
   92/100 cases agree to <1e-9, 8 move, positions apart by up to 11.5. Bit
   equality is the WRONG gate there; `l117_linux_verify.judge48()` checks the
   shipping invariant instead (every case feasible, none worse than the pre-LP
   anchor, total still ahead) — which holds on both stacks.
4. **A probe must mirror `lp_pass`'s cluster re-freeze loop.** `hard_ok` does not
   test contiguity, so split clusters slip past it. The first long-step probe
   scored 66/100 at s=1 where `dep_case` gets 100/100. **Give every probe a
   "degenerate case must reproduce a known value" self-gate.**
5. **`hard_ok` sees none of MIB / boundary / cluster contiguity.** Only the
   official `evaluate_solution` does.
6. **`is_feasible` is not just overlap** — it also covers fixed-shape and
   preplaced dimensions. A first cut that reshaped locked MIB members turned
   63/100 held-out cases infeasible (cost 1.53 → 7.62).
7. **`dep_case`'s guard cannot accept a violation repair.** `better = hpwl or
   area improved`, `worse = any of hpwl/area/vrel worsened` ⇒ a pass that only
   improves vrel fails the `better` test.
8. **Do not fit the cost function.** A least-squares fit gives
   `1 + 0.488h + 0.514a + 2.584v`; the real one is multiplicative with
   `exp(2*V_rel)` (`compute_cost`, ALPHA=0.5 BETA=2.0 GAMMA=0.3).
9. **`verify_final_tar.sh` is not a file** — it is a string embedded in
   `m67c_make_linux_bundle.py`. This box now has WSL2 (Ubuntu 26.04, py3.14.4,
   gcc 15.2), so use `ship_final/l117_linux_verify.py` instead.
10. **`regression_suite.py` must be run from PowerShell** (the Bash tool's
    sandbox blocks `.exe` writes ⇒ m48 reports a false FAIL).

## 7. Where the score actually is

- **The time side is spent.** Weighted RF **0.7042** against a floor of 0.7000;
  49/100 cases already on it, and the 51 above carry only **8.2%** of the weight.
- **The score is twelve cases.** Weight is `exp(n/12)` ⇒ the top-10 hold **54.6%**
  of the weighted excess and the top-20 hold **78.6%**, all n >= 109.
- **On those cases the deficit is topological.** Wirelength excess vs the label
  is +24%, of which only ~7pp is "our floorplan is bigger" — **+15.7% survives
  scale normalisation**. It is not pin-driven (p2b is 10.4%), not concentrated
  (top-1% of edges carry 10-20%), and ~85% of blocks carry a different aspect
  than the label. The shape LP already solves exact linear HPWL under our fixed
  topology, so that 15.7% is out of reach without changing topology.
- **Perfect information into the packer is capped at ~0.1%**: perfect ordering
  +0.005% (M26), perfect position seeds +0.001% (M68), perfect shapes +0.099%
  (M79), against a 14.343% gap to the label floor.
- **κ = 3.161 is calibrated, not guessed** — back-solved from the alpha round's
  real result (Rank 3, official 1.0286, cost-weighted RF 0.7081). So s=1 IS the
  calibration and `SPEEDS=[0.5, 2.5]` is its uncertainty band. The official RF
  denominator is the **cross-submission median** (other teams), not our own
  reference; the local evaluator forces it to 1.0.
